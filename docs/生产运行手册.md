# 生产运行手册

本手册覆盖试点和中级企业部署所需的数据库、多实例、可观测性、告警、审计留存与灾备。微信支付和退款本轮保持关闭。

## 1. 发布前配置

- 复制 `.env.example` 为 `.env`，密钥由 Secret Manager 或部署平台注入。
- `NODE_ENV=production`、`DATA_STORE=postgres`、`WX_MOCK=false`、`WX_PAYMENT_ENABLED=false`。
- 使用真实小程序 `WX_APPID`/`WX_SECRET`，按微信公众平台模板填写 `WX_SUBSCRIBE_TEMPLATES`。
- `AUTH_SECRET`、管理员口令、平台运营口令、`METRICS_TOKEN` 使用高强度独立随机值。
- 上传、审计归档和备份目录不得放在容器临时层；数据库、品牌素材和审计归档必须分别备份。

启动时会校验生产关键配置。缺失项会直接失败，不会静默使用默认口令或 mock 支付。

## 2. 数据库与进程

```powershell
npm run db:migrate
npm run db:status
```

Web 副本和后台任务的分工见 [多实例部署.md](多实例部署.md)。核心要求是：

- 所有 Web 实例连接同一 PostgreSQL；
- Web 实例关闭 `OUTBOX_WORKER_ENABLED`、`AUDIT_ARCHIVE_WORKER_ENABLED` 和两个业务定时器；
- 专用 Task worker 开启上述 worker；
- 负载均衡只把流量发给 `/readyz` 返回 200 的实例；
- 滚动发布后检查连接池、5xx、P95、Outbox 积压与归档失败。

## 3. 指标和日志

### Prometheus

`GET /metrics` 输出 Prometheus 文本格式，必须携带 `Authorization: Bearer <METRICS_TOKEN>`。可直接使用
[prometheus.example.yml](../deploy/observability/prometheus.example.yml) 和
[wechat-saas.rules.yml](../deploy/observability/wechat-saas.rules.yml)。建议抓取配置：

```yaml
scrape_configs:
  - job_name: wechat-saas
    metrics_path: /metrics
    authorization:
      credentials: ${METRICS_TOKEN}
    static_configs:
      - targets: ["api-a:3100", "api-b:3100", "task-worker:3100"]
```

建议告警：

```yaml
groups:
  - name: wechat-saas
    rules:
      - alert: SaaSInstanceDown
        expr: up{job="wechat-saas"} == 0
        for: 2m
      - alert: SaaSHigh5xxRate
        expr: |
          sum(rate(saas_http_requests_total{status=~"5.."}[5m]))
          /
          clamp_min(sum(rate(saas_http_requests_total[5m])), 0.001)
          > 0.05
        for: 5m
      - alert: SaaSSlowP95
        expr: |
          histogram_quantile(0.95,
            sum by (le, route) (rate(saas_http_request_duration_seconds_bucket[5m]))
          ) > 1
        for: 10m
      - alert: SaaSOutboxDeadLetters
        expr: saas_outbox_dead_letters > 0
        for: 5m
      - alert: SaaSOutboxBacklog
        expr: saas_outbox_failed > 20
        for: 5m
```

进程内告警 webhook 作为补充：`ALERT_WEBHOOK_URL`、`ALERT_WEBHOOK_TOKEN`、`ALERT_COOLDOWN_MS`。
当窗口内出现 3 个 5xx、错误率超过 5% 或记录服务端异常时，发送 JSON POST。该通道不能替代 Prometheus、APM、
集中日志和独立值班告警。

### 日志

应用输出 JSON Lines，每条 HTTP 日志包含 `requestId`、方法、路径、状态码、耗时、租户和操作者类型。

- `LOG_FILE` 可写入本地文件，按 `LOG_MAX_BYTES` 和 `LOG_MAX_FILES` 轮转；
- 生产建议同时采集 stdout 到集中日志平台，并按 `requestId` 关联错误；
- 告警应接入企业微信、短信或 PagerDuty 等独立值班通道；
- 日志中不得写入明文口令、完整令牌、微信密钥、支付私钥或用户敏感资料。

宿主机或容器平台还应采集 CPU、内存、磁盘、数据库连接数、备份失败和队列积压。

## 4. 审计留存

应用层为每个租户维护连续 SHA-256 链。PostgreSQL 触发器拒绝改写和删除已封存审计。`AuditArchiveService`
将增量按租户分段归档：

- 本地模式使用一次性创建和只读权限，适合演练，不是物理 WORM；
- S3 兼容模式设置 `x-amz-object-lock-mode` 与保留截止时间，Bucket 必须预先启用 Object Lock；
- `AUDIT_S3_OBJECT_LOCK_MODE=COMPLIANCE` 用于法定留存；`GOVERNANCE` 仅适合有严格例外审批的场景；
- 归档清单记录范围、条数、SHA-256、存储位置和保留期；
- 运营台“运营保障”可查看完整性、执行归档并在异常时定位。

生产至少执行：数据库最小权限、对象存储最小权限、跨地域副本、定期校验、法务确定的保留周期和恢复演练。
数据库超级用户仍可更改表或触发器，因此数据库审计只能作为应用防篡改层，不能替代云端 WORM 与异地归档。

## 5. 通知 Outbox

支付提醒、取货提醒、退款和售后通知先写持久化 Outbox，再由 worker 发送。发送失败进入指数退避，超过最大次数成为
死信。运营台可筛选、重试和手动运行一批。多实例通过数据库行锁和租约避免并发重复认领。整体为至少一次投递；
微信已接收但状态落库前崩溃时可能重发，不能宣称严格恰好一次。

上线前用真实测试账号逐项验收：

- 获得模板授权，记录 `accept/reject/ban/filter`；
- 确认模板字段长度、占位符和跳转页符合微信要求；
- 验证拒绝授权后主业务仍成功；
- 验证网络失败、模板失效和 access token 过期会进入重试或死信；
- 在发送记录中核对 openid、模板 ID、请求时间和微信错误码。

## 6. 备份与灾备

创建加密快照：

```powershell
npm run backup -- --backend=postgres .\backups
```

隔离恢复：

```powershell
npm run restore -- .\backups\wechat-saas-postgres-2026-11-23T00-00-00.snapshot.json `
  --database-url="postgresql://restore_user:***@restore-host/wechat_saas_restore" `
  --allow-overwrite
```

文件后端恢复必须指向新目录或显式 `--force`。PostgreSQL 恢复必须指向隔离数据库并显式 `--allow-overwrite`。
完整恢复会替换运行时集合，并写回上传素材；目标库中的旧集合不会被保留。生产恢复应使用仅对隔离恢复库有写入权限的
专用账号，不得把恢复账号用于 Web 服务。

发布前的灾备验收：

1. 记录最后业务写入时间、备份完成时间和恢复完成时间。
2. 恢复数据库与上传素材，核对租户、商品、订单、金额、审计链头和 Outbox 条数。
3. 在隔离环境启动应用，验证登录、订单、售后、导出和 `/readyz`。
4. 将结果写入带日期、环境、版本、RPO/RTO 和差异清单的演练报告。
5. 生产目标 RPO/RTO 由业务方确认；当前试点的秒级数字仅是小型隔离样本，不能直接代表生产 SLA。

## 7. 生产切换和回滚

- 切换前冻结写入、生成快照、校验摘要并保留旧版本只读。
- 新版本先在隔离库跑验收，再逐步放量。
- 回滚必须基于已校验快照和已知版本，不能在未知数据库状态上直接重跑旧代码。
- 发生安全事件时撤销管理员会话、轮换 `AUTH_SECRET` 和外部密钥、保全日志及审计归档，再恢复服务。

## 8. 当前外部验收边界

- 仓库仍不能在没有合法 AppID、订阅模板、用户授权和公网域名时证明真实微信送达。
- 生产启动会拒绝 `touristappid`，必须替换为真实小程序 AppID；这只能防止误发布，不能替代真实登录和订阅送达验收。
- 微信支付和退款按本轮要求保持关闭；支付密码学单元测试不代表真实商户资金流验收。
- 2026-11-23 只验证了本地只读审计归档；S3 Object Lock 尚未对真实云账号执行端到端验收。
- 备份恢复已在隔离环境验证，但生产 RPO/RTO 仍取决于数据库 PITR、对象存储复制、网络和演练频率。
