# 数据库迁移方案（JSON → PostgreSQL）

当前代码使用 `JsonStore`（本地 JSON + 原子写入）承载所有集合，适合本地演示与单机小规模
场景，但存在以下企业级缺口：

1. 多集合写操作（下单扣库存/扣积分/预留优惠券）无跨集合事务；
2. 无唯一约束与行锁，多实例部署时会出现并发竞态；
3. 全量扫描列表，缺少索引与分页（API 层已加分页，存储层仍需索引）。

## 目标 Schema

完整 PostgreSQL 建表脚本见 [db/migrations/001_init.sql](../db/migrations/001_init.sql)，涵盖：

- 租户/管理员（角色）/会员/地址
- 商品/分类/库存（可用库存 + 预留库存）
- 优惠券模板/优惠券实例（reserved/used/released 状态）
- 团购/参团记录
- 订单/订单明细/支付单/退款单
- 积分流水、预约、问卷、审计日志
- 订阅套餐/租户订阅

核心约定：

- 金额一律用 **integer 分** 存储（与现有商品/订单逻辑一致，优惠券也已统一为分）；
- 所有业务表带 `tenant_id` 外键，保证租户隔离；
- 订单号 `order_no`、支付 `out_trade_no`、退款 `out_refund_no` 加唯一约束；
- 关键查询列建索引（tenant、status、member、service+date）。

## 迁移步骤

1. 在 PostgreSQL 中执行 `db/migrations/001_init.sql`；
2. 新增 `src/store/PgStore.js`，实现与 `JsonStore` 相同的接口
   （insert/findById/update/remove/find/count/markDirty），内部用参数化 SQL；
3. 在 `src/index.js` 按 `DATA_STORE=postgres` 选择存储实现；
4. 把跨集合的业务动作（下单、支付、退款、核销）放入数据库事务，用
   SELECT ... FOR UPDATE 或原子 UPDATE ... WHERE stock >= qty 扣库存；
5. 用 `node:sqlite`（本机可用）先做 ACID 中间层联调，再切换 PostgreSQL；
6. 数据迁移：写一次性脚本从 data 目录的 JSON 读取并导入 PostgreSQL，校验行数与金额。

## 备份与恢复

- 快照备份：`node scripts/backup.js`，将 DATA_DIR 集合复制到时间戳目录；
- PostgreSQL 建议使用 `pg_dump` 定期全量 + WAL 归档；
- 恢复演练：定期在隔离环境恢复备份，核对订单数与金额合计。
