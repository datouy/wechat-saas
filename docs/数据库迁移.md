# 存储选择与 PostgreSQL 迁移

项目提供三种运行时存储，共用同一套业务接口：

| `DATA_STORE` | 适用场景 | 一致性 | 多实例能力 |
| --- | --- | --- | --- |
| `json` | 本地演示和调试 | 单进程原子写文件 | 不适合横向扩容 |
| `sqlite` | 单机试点、单写节点 | WAL、事务、原子库存扣减 | 共享可靠卷才可有限多进程 |
| `postgres` | 生产多实例 | 连接池、跨实例事务、行锁、查询索引 | 推荐 |

## PostgreSQL 运行时模型

`PgStore` 已接入 `src/index.js`，不再只是目标设计。`001_init.sql` 和
`002_pilot_enterprise.sql` 提供规范化业务投影；`003_runtime_pgstore.sql` 提供当前文档式业务接口使用的
`saas_documents` 表和租户、会员、状态、Outbox 到期时间索引。两种模型可并存，后续可把高频报表逐步投影到规范表。

运行时具备以下保证：

- 事务上下文使用独立连接，嵌套调用复用同一事务；
- `findByIdForUpdate` 提供行锁；
- 库存使用锁内读取与原子更新，已验证 60 路并发仅成功 50 次；
- `lock()` 使用 PostgreSQL advisory transaction lock，Outbox 与审计归档可跨实例抢占；
- 已封存审计文档拒绝 `UPDATE` 和 `DELETE`；
- 连接池默认最多 20 条，可配置超时和 TLS。

## 首次部署

1. 为应用创建独立数据库、迁移账号和运行账号；运行账号不应拥有超级用户或关闭触发器的权限。
2. 配置 `DATABASE_URL`、`DATABASE_SSL=true`、`PG_POOL_MAX`。
3. 执行并核对迁移：

```powershell
$env:DATA_STORE="postgres"
$env:DATABASE_URL="postgresql://app_user:***@db.internal:5432/wechat_saas?sslmode=require"
npm run db:migrate
npm run db:status
```

4. 启动应用前确认 `/healthz` 与 `/readyz` 均正常，`/readyz` 应包含存储探针。
5. 首次空白库会生成演示数据；正式开通租户仍从平台运营台或受控初始化流程执行。

迁移文件被执行后会记录 SHA-256；若历史迁移文件被修改，脚本会拒绝继续。新增结构应使用新迁移文件。

## 从 JSON 或 SQLite 切换

现有运行库尚无自动的 JSON/SQLite 到 PostgreSQL 数据搬运命令，不能只改 `DATA_STORE`。正式切换应执行：

1. 在业务低峰冻结写入，完成一次带清单校验的加密快照。
2. 将快照中的集合按 `id` 和 `tenantId` 导入隔离 PostgreSQL 库。
3. 对租户、会员、商品、订单、金额合计、优惠券、积分、审计链头和 Outbox 数量做双向核对。
4. 在隔离环境启动 PostgreSQL 版本，完成登录、下单、支付 mock、退款 mock、核销、售后和导出验收。
5. 切换流量并保留旧库只读，观察至少一个完整订单履约周期后再决定下线。

第 2 步属于一次性受控数据迁移；不要用演示种子数据覆盖现有租户。

## 索引与扩展边界

- 当前谓词仍在 Node.js 侧执行，适合现有业务规模和统一文档接口；大规模报表应增加 SQL 投影或物化视图。
- 极高订单量下，关系表投影和异步统计会成为下一阶段优化项。
- 应用内限流仍为实例内存；多实例生产应在网关层限流，或扩展共享 Redis 计数器。

## 回归证据

`npm run test:postgres` 会启动隔离的 PostgreSQL 17，应用 `001` 至 `003`，并验证应用启动、管理员登录、并发库存、双 worker、审计触发器及加密备份恢复。2026-11-23 的结果为 `6/6`。
