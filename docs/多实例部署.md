# 多实例部署说明

本项目在单机单进程下即可完整运行；以下说明面向水平扩容（多实例）场景，并明确当前已支持与尚需外置的部分。

## 存储层

- 默认 DATA_STORE=json 是「单进程内存 + 原子文件落盘」，仅适合单实例。
- 多实例必须使用 DATA_STORE=sqlite：SqliteStore 已开启 WAL、busy_timeout=5000、synchronous=NORMAL，配合共享文件系统（NFS/共享卷）即可多实例并发读写。
- 更稳妥的做法：多实例共用一个 SQLite 文件，但让所有写请求走同一节点或引入分布式锁；atomicDec 的 BEGIN IMMEDIATE 已能保证库存扣减在并发下的正确性（防超卖）。

## 定时后台任务（幂等，但应避免每实例重复跑）

两个定时器均每 60 秒触发，且幂等（先校验状态再更新）：

- 订单超时取消 / 配送超时自动完成：OrderManager._housekeeping
- 团购超时自动关闭：GroupBuyManager._autoCloseExpired

多实例下建议只在一个「后台任务实例」开启，其余实例关闭，减少无谓的写锁竞争：

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| ORDER_HOUSEKEEPING_ENABLED | true | 设为 false 关闭订单定时任务 |
| GROUPBUY_AUTOCLOSE_ENABLED | true | 设为 false 关闭团购超时自动关闭 |

## 接口限流（当前为单进程内存，多实例各自计数）

express-rate-limit 默认使用进程内存计数，多实例下每个实例独立计数，总限额会随实例数放大。两种处理方式：

1. 由网关/负载均衡统一限流：设置 RATE_LIMIT_DISABLED=true 关闭应用内限流，交给 Nginx/Kong/云网关。
2. 共享限流存储：接入 Redis（如 rate-limit-redis），使各实例共享同一计数器。当前代码未内置 Redis 依赖，需自行扩展 src/index.js 的限流中间件。

## 推荐拓扑

- 网关/LB：统一限流、TLS、WAF。
- API 实例（可多个）：DATA_STORE=sqlite，ORDER_HOUSEKEEPING_ENABLED=false，GROUPBUY_AUTOCLOSE_ENABLED=false。
- 后台任务实例（一个）：DATA_STORE=sqlite，定时器开启，可关闭对外端口。
- 共享存储：所有实例指向同一 SQLite（WAL）文件。

## 尚未内置、需要外部组件的能力

- 共享限流计数（Redis）——见上文。
- 分布式任务去重：定时器幂等，无需强锁；若未来加入「到期即发消息」等非幂等任务，需引入分布式锁或单实例执行。
- 会话/令牌存储：JWT 无状态，天然适合多实例；但若需要「踢人下线/主动失效」，需外置黑名单（Redis）。
