# 多实例生产部署

多实例部署要求 `DATA_STORE=postgres`。JSON 只用于开发；SQLite 适合单机或单写节点，不应把共享文件系统当作横向扩容方案。

## 推荐拓扑

```text
Internet
   |
HTTPS / WAF / Gateway
   |
Load Balancer
   |-- Web A  (API + 管理端 + 顾客端，后台 worker 关闭)
   |-- Web B  (API + 管理端 + 顾客端，后台 worker 关闭)
   |-- Web N  (扩展副本)
   |
   |-- Task worker (Outbox + 审计归档 + 订单/团购定时任务)
   |
PostgreSQL (TLS, 连接池，PITR)
   |
Object storage (审计 Object Lock + 异地副本)
```

任务进程可以复用同一镜像并仅监听内网端口，也可以构建一个不对外暴露的启动入口；核心是确保同一类非幂等后台任务只有受控 worker 执行。

## 进程配置矩阵

| 配置 | Web 实例 | Task worker |
| --- | --- | --- |
| `DATA_STORE=postgres` | 是 | 是 |
| `OUTBOX_ENABLED` | `true` | `true` |
| `OUTBOX_WORKER_ENABLED` | `false` | `true` |
| `AUDIT_ARCHIVE_ENABLED` | 按归档策略 | 按归档策略 |
| `AUDIT_ARCHIVE_WORKER_ENABLED` | `false` | `true` |
| `ORDER_HOUSEKEEPING_ENABLED` | `false` | `true` |
| `GROUPBUY_AUTOCLOSE_ENABLED` | `false` | `true` |

Web 实例关闭 worker 不等于关闭入队：订单、退款、取货等业务动作仍会写持久化 Outbox。`kick()` 同样遵守
`OUTBOX_WORKER_ENABLED`，不会在请求进程中偷偷发送。

## Outbox 可靠性

- 业务请求先落库，进程在发送前退出不会丢失待发送记录。
- worker 通过事务、行锁和租约认领记录，多实例并发测试中同一条消息只发送一次。
- 整体语义是至少一次投递：微信已接收但最终状态尚未落库时进程崩溃，租约到期后可能再次发送。微信订阅消息接口不提供调用方可控的幂等键，因此试点必须按此边界验收。
- 失败使用指数退避，达到 `OUTBOX_MAX_ATTEMPTS` 后进入死信；运营台可筛选并人工重试。
- `POST /api/admin/outbox/run` 仅用于受控补跑；正常生产应依赖 worker。
- 微信真实送达、用户授权和模板字段仍需合法 AppID 与用户环境验收。

## 审计归档 worker

- `AUDIT_ARCHIVE_WORKER_ENABLED=true` 的实例每隔 `AUDIT_ARCHIVE_INTERVAL_MS` 执行一次归档。
- 文档存储和 PostgreSQL 触发器阻止改写已封存审计；对象存储端使用 S3 Object Lock 形成 WORM。
- 只有对象写入成功后才记录 `auditArchives`，归档失败会留在错误列表并写结构化日志。
- S3 凭据只授予目标桶的 `PutObject`、`GetObject` 和必要的保留策略能力；禁止使用全局管理员密钥。

## 网关与安全头

应用已启用 Helmet、CSP、同源写操作校验、请求 ID、登录限流和会话撤销。生产网关仍需：

- TLS 终结、HSTS、请求体上限和 DDoS/WAF 策略；
- 统一限流；应用内 `express-rate-limit` 是单实例内存计数，可通过 `RATE_LIMIT_DISABLED=true` 交给网关；
- 仅信任实际负载均衡器传入的代理头，避免伪造客户端 IP；
- 对 `/metrics` 仅允许 Prometheus 网段访问，并保留 `METRICS_TOKEN`。

管理员会话版本存储在数据库中，撤销后所有实例立即拒绝旧令牌。

## 无状态扩缩容检查

1. 所有实例连接同一 PostgreSQL，并设置合理的 `PG_POOL_MAX`；总连接数不得超过数据库连接上限。
2. 所有实例的 `AUTH_SECRET` 一致。
3. 上传目录使用共享对象存储或共享卷；数据库备份和上传素材恢复必须成对演练。
4. 只让 Task worker 开启订单、团购、Outbox 和归档定时器。
5. 滚动发布时先启动新实例，确认 `/readyz` 为 `ok`，再摘除旧实例。
6. 发布后检查 5xx、P95、Outbox 死信、审计归档失败和队列积压。

## 当前边界

- 应用限流没有内置 Redis 共享计数；应由网关承担或另行扩展。
- 指标、最近错误和进程内告警按实例保存；跨实例视图必须由 Prometheus/APM 聚合。
- 多门店和租户数据隔离已具备；租户品牌素材目前依赖共享上传卷/对象存储配置，生产应保证多实例可见性。
