# 微信小程序上线清单

本轮可上线微信登录与订阅消息准备链路，微信支付/退款保持关闭。真实送达和资金流不能只靠本地 mock 证明。

## 1. 账号与域名

- [ ] 小程序主体认证完成，取得合法 `WX_APPID` 和 `WX_SECRET`。
- [ ] 服务器域名配置为公网 HTTPS，并完成备案、证书续期和 TLS 检查。
- [ ] 请求域名、上传域名和业务域名与部署环境一致。
- [ ] 隐私保护指引已声明实际收集的资料，包括地址、手机号、订单与履约信息。
- [ ] 小程序版本、类目、客服和投诉入口符合主体资质要求。

仓库中的 `touristappid` 只用于开发者工具预览，不是生产 AppID。

## 2. 登录

- [ ] `WX_MOCK=false`，生产启动配置校验通过。
- [ ] 小程序 `wx.login` 获取的临时 code 能通过真实 `code2Session` 换取 openid。
- [ ] 同一微信用户刷新或重新进入后仍对应同一会员记录。
- [ ] 非法 code、微信接口超时和 AppSecret 错误有明确日志及用户提示。
- [ ] 会员令牌、管理员令牌和平台令牌彼此隔离。

## 3. 订阅消息

1. 在微信公众平台选择并启用订单支付、取货、退款、售后等模板。
2. 把真实模板 ID、跳转页和字段映射配置到管理端“消息中心”或 `WX_SUBSCRIBE_TEMPLATES`。
3. 小程序只在用户真实操作前调用 `wx.requestSubscribeMessage`，并逐模板上报授权结果。

需要的真实验收：

- [ ] 管理端保存模板后，小程序能读取当前租户配置。
- [ ] 用户接受、拒绝、永久拒绝和系统过滤四种结果均被记录。
- [ ] 拒绝授权不影响下单、支付（启用后）或主业务动作。
- [ ] 支付成功、发货/待取、取货提醒、退款处理中/完成、售后更新均生成正确 Outbox 记录。
- [ ] 实际微信账号收到消息，模板字段长度和跳转页正确。
- [ ] 网络失败、access token 过期、模板失效进入重试或死信，运营台可识别和重试。
- [ ] 投递记录包含 openid、模板 ID、尝试次数、微信错误码和时间。

模板授权只能由用户在客户端触发，服务端不能代替用户接受授权。

## 4. 微信支付（本轮关闭）

- [ ] `WX_PAYMENT_ENABLED=false`，生产接口对真实支付请求返回明确的未启用错误。
- [ ] 取得合法商户号、API v3 密钥、API 证书、平台证书和公网回调域名后再另立支付上线验收。
- [ ] 届时完成下单签名、金额校验、支付回调验签、幂等、退款回调、账单对账和异常补偿。
- [ ] 不把本地 RSA/AES 往返测试当作真实商户资金流验收。

## 5. 部署与运营

- [ ] 按 [生产运行手册.md](生产运行手册.md) 检查数据库、指标、日志、告警、Outbox、审计和备份。
- [ ] 配置客服和售后入口，确认经营人员知道死信、超时履约和异常订单处置流程。
- [ ] 用未接触过项目的人员完成 [README.md](../README.md) 的十分钟路线。
- [ ] 记录实际 AppID 尾号、模板 ID 尾号、测试账号、时间、结果和追踪号；报告中不要保存完整密钥。

## 6. 当前已知边界

- 没有合法 AppID 和模板 ID 时不能证明真实订阅送达。
- 没有真实商户资质时不能完成支付/退款上线。
- 开发者工具“测试号”仅能验证页面和 mock 业务链路。
